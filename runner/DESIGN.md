# The runner: how a Strategy Lab bot will trade on a user's own account

Status, 2026-11-14: part 1 (the signal hub, paper only) is in this folder. Part 2 (the executor) and part 3 (sign-up) are
designed here and not built. Nothing in this repo or on this server will ever hold a user's key.

## What it is for

The Strategy Lab shows what open-source bots did with paper money. The runner lets someone pick one of those bots and have
it trade on **their own** exchange account, without running a server. TradingAgentStack is paid by the exchange through
its builder or broker program (a share of the exchange's own fee on orders we send), never by holding anyone's money.

## The three parts

```
Strategy Lab bots ──► 1. Signal hub ──► signals.json ──► 2. Executor ──► user's own account (Hyperliquid first)
 (frozen files)        paper copies,      every fill        per-user        trade-only access, our builder code
                       no keys            as it happens     limits                 ▲
                                                                                    │
                                                         3. Sign-up page ───────────┘
                                                            the user's wallet signs two approvals, once
```

### 1. Signal hub (built: `runner/hub.py`, compose service `runner-signals`, off until enabled)

- Runs a live dry-run copy of each bot in `runner/strategies.json`, each its own Freqtrade process, on the lab's own frozen
  file (refused if its SHA-256 differs from the one the lab recorded) and the lab's own config: same 20 coins, same rules,
  same $1,000 paper wallet.
- Freqtrade's webhook posts every entry and exit fill to a collector in the same container (127.0.0.1 only). Fills are kept
  one JSON line each and published at `https://workers.tradingagentstack.com/runner/signals.json`.
- Enabling it: each copy needs about 250 MB. The server (2 vCPU, 4 GB) already runs both labs, which use up to 3.5 GB
  between 04:00 and 06:00 UTC. Resize the server first, then start it with `COMPOSE_PROFILES=runner` in the server's
  environment (deploy.sh runs `docker compose up -d`, which skips profiled services otherwise).

### 2. Executor (to build, as its own service, never on this server)

- Reads `signals.json` and copies each fill into every subscribed user's account:
  - The lab's bots trade spot, long only, on Binance prices. On Hyperliquid the executor opens a **1x long perpetual** on the
    same coin, so the user holds the same exposure. Funding is paid or received, and the page must say so.
  - Size: the fill's stake as a share of the bot's $1,000 paper wallet, times the user's budget. An exit closes the
    position with a reduce-only order.
  - Every order carries TradingAgentStack's Hyperliquid builder code at 0.02% (`f: 20`), the rate the user approved.
- Built on TAS Guard's Hyperliquid mode rather than new code: Guard already signs Hyperliquid orders with an API wallet,
  byte-checked against the official SDK's vectors, and enforces per-order and daily caps, a kill switch and a hash-chained
  audit log. The executor is Guard with many accounts instead of one.
- Limits per user, enforced before any order: budget (never more than the user set), daily loss stop, max open positions,
  pause on two failed orders in a row, and a global kill switch that stops every account at once.
- Keys: one Hyperliquid API ("agent") wallet per user, generated by the executor. An agent wallet can place and cancel
  orders but cannot withdraw (Hyperliquid's own rule). Its key is encrypted with a cloud KMS key and only decrypted in
  memory to sign. The executor runs as a separate deployment with its own access controls and logs, never in this public repo's server.
- OKX and Bybit come next, through OKX's AI Builder Program (OAuth, so no key is pasted) and Bybit's broker program.

### 3. Sign-up (to build, on tradingagentstack.com)

1. The user picks a bot and a budget, and enters an email for alerts.
2. The user connects their own wallet in the browser. It signs two Hyperliquid actions, both shown in plain words first:
   - `approveAgent`: lets the executor's new agent wallet trade on the account, with an expiry date. It can't withdraw.
   - `approveBuilderFee`: allows TradingAgentStack's builder fee of up to 0.02% per trade. Hyperliquid requires the main
     wallet to sign this, not an agent wallet.
3. Paper first: the bot runs on a paper account for 7 days, with the same alerts, before the user can switch it to live.
4. Stop at any time from the site or Telegram. Revoking the agent in Hyperliquid's own app also stops it, without us.

## Rules

- Never a seed phrase, never a withdrawal permission, never custody.
- The order of the Strategy Lab never depends on what a bot earns us. We earn the same rate on every bot.
- Results shown to a user are after all fees, including ours.
- Live money only after a lawyer has looked at it (copy trading and automated trading for other people are regulated in
  some countries) and with the countries the venue does not serve blocked.
